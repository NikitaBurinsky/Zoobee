# Security Baseline (Lightweight)

Связанные записи: [Risks And Debt](../RISKS_AND_DEBT.md), backlog `DOC-016`, `DOC-036`.

## Текущий baseline

- Документация не содержит секретных значений.
- Секреты в code/config считаются инцидентом качества и фиксируются в risk register.
- Любые новые ключи/API tokens должны идти через env/secrets manager.

## Минимальные обязательные практики

- Не коммитить реальные пароли/ключи/токены в `appsettings*.json`.
- Не логировать секреты в plaintext.
- Не добавлять абсолютные локальные пути в production-ориентированный конфиг.

## Remediation plan (по этапам)

1. Ротация и удаление текущих скомпрометированных значений из репозитория.
2. Перенос всех чувствительных параметров в secure storage.
3. Добавление проверок в CI (secret scan + config lint).
4. Обновление runbook’ов после перехода.
